## Project Description

A simple REST API called **Cooking Recipes API** built with **Node.js** and **Express 5**. It manages a list of cooking recipes stored in memory as a JavaScript array of objects in `routes/recipes.js` (no database, no front-end framework).

Each recipe object has:
- `id` (number, automatically generated by the API)
- `title` (string)
- `category` (string)
- `prepTimeMinutes` (number)
- `servings` (number)
- `difficulty` (string)

## API Routes

| No | Method | Path | Purpose | Success Code | Error Code(s) |
| --- | --- | --- | --- | --- | --- |
| 1 | `GET` | `/` | Welcome message with student name and theme | `200` | - |
| 2 | `GET` | `/recipes` | List all recipes | `200` | - |
| 3 | `GET` | `/recipes/:id` | Get one recipe by `id` | `200` | `404` (unknown id) |
| 4 | `POST` | `/recipes` | Add a new recipe (`id` auto-generated) | `201` | `400` (missing/invalid fields) |
| 5 | `PUT` | `/recipes/:id` | Update an existing recipe | `200` | `400` (invalid fields), `404` (unknown id) |
| 6 | `DELETE` | `/recipes/:id` | Delete a recipe (requires demo token header) | `200` | `401` (missing/wrong token), `404` (unknown id) |
| 7 | `GET` | `/recipes/category{/:name}` | Filter recipes by category, or list all when `:name` is omitted | `200` | - |
| 8 | `GET` | `/files/*path` | Return the wildcard path segments as an array | `200` | - |
| 9 | Any | `/*` (unknown URL) | Handled by the 404 handler | - | `404` |

## Example JSON Bodies (`POST` and `PUT`)

Do **not** include `id` when sending a `POST` or `PUT` request — the API generates and manages `id` automatically.

### `POST /recipes`
```json
{
  "title": "Avocado Toast",
  "category": "Breakfast",
  "prepTimeMinutes": 10,
  "servings": 1,
  "difficulty": "Easy"
}
```

### `PUT /recipes/1`
```json
{
  "title": "Nasi Goreng Kampung",
  "category": "Main Course",
  "prepTimeMinutes": 25,
  "servings": 2,
  "difficulty": "Easy"
}
```

## Demo Auth Header for `DELETE`

The `DELETE /recipes/:id` route is protected by `requireAuth` in `middleware.js`. You must send this request header:

- **Header Name:** `x-api-key`
- **Header Value:** `recipes-demo-token-2026`

If the header is missing or has any other value, the API returns `401 Unauthorized`.

## Middleware and Order in `index.js`

Express runs middleware and routes **from top to bottom** in the order they are registered in `index.js`:

1. **Logger & JSON parser (`app.use(logger)`, `app.use(express.json())`):**
   - `logger` runs first on every request to print the HTTP method and URL in the terminal.
   - `express.json()` parses incoming JSON request bodies so `req.body` is available in `POST` and `PUT`.
2. **Routes (`GET /`, `app.use('/recipes', recipesRouter)`, `GET /files/*path`):**
   - Express checks each route in order. When a route matches and sends a response, the pipeline stops there.
   - Inside `routes/recipes.js`, `/category{/:name}` is registered **before** `/:id` so the word `"category"` is not treated as an `:id`.
   - `requireAuth` is attached directly to `DELETE /recipes/:id` so only delete requests require the `x-api-key` token.
3. **404 handler (`app.use(notFound)`):**
   - Placed after all valid routes. If no route matched the request URL, `notFound` creates a `404` error and passes it to `next(error)`.
4. **Error handler (`app.use(errorHandler)`):**
   - A 4-parameter function `(err, req, res, next)` placed **last** in `index.js`.
   - Any error passed to `next(err)` or thrown inside an `async` route (such as a missing recipe `id`) lands here and returns a consistent JSON error response:
     ```json
     {
       "error": true,
       "status": 404,
       "message": "Recipe with id 999 not found"
     }
     ```

If the 404 handler or error handler were placed before the routes, valid routes would never be reached or errors thrown by routes would not be caught.
